# ADR-0006：分布式运行时改造

- 状态：已采用
- 日期：2026-09-16
- 更新：2026-10-14 —— 改造已完成；部署形态最终定为单实例多进程

## 背景

改造前，多处运行时状态绑定在进程内存中。这带来两个后果：**进程重启会丢东西**（正在跑的任务直接消失），以及**长任务会堵住短任务**（转写占着 API 进程的线程，页面请求只能干等）。

| 位置 | 进程内状态 |
| --- | --- |
| `services/retrieval/bm25_service.py` | `corpus` / 文档 id 列表，纯内存无持久化 |
| `services/runtime/agent_runtime_service.py` | 事件列表、`threading.Event` 取消信号、`_active_sessions` 会话锁 |
| `services/ingestion/asr_service.py` | `_running_audio_ids` 去重集合 |
| `services/wiki/` 原索引 worker | 每 5 秒轮询数据库，无跨进程任务抢占 |

## 决策

**算法与业务逻辑不变，只把状态从进程内存搬到共享存储、把执行从进程内线程搬到独立进程。**

1. 业务库由 SQLite 迁移到 MySQL 8。**SQLite 已完全移除**，不再作为测试替身——测试连真实 MySQL 上的独立测试库，保证测试与生产在同一种方言上。
2. 引入 Redis，一个组件承担四件事：任务队列（arq）、事件流（Streams）、取消信号（key）、会话锁（`SET NX EX`）。
3. 后台任务由进程内协程迁移到 arq worker 进程。三个队列按时长与性质分开：索引（并发 10）、语音转写（并发 4）、Agent 运行（并发 4）。索引任务改为写入时直接入队，取消 5 秒轮询。
4. Agent 的**执行本身**也搬进 worker。这一条不在原计划里，但必须有：留在 API 进程的话，API 一重启就会打断正在跑的对话，而一次运行最长 180 秒。
5. ChromaDB 保留，仅由 `PersistentClient` 改为 `HttpClient` 连独立容器。
6. 混合检索算法（BM25 + 向量 + RRF + Rerank）不做任何改动。BM25 索引仍留在各进程内存里，Redis 上只放一个**版本号**——实测词表快照是负收益（973 个分块全量重建只要 399 毫秒，快照净省约 211 毫秒，却要背上序列化兼容、反序列化安全面和写入侧分布式锁）。

### 部署形态：单实例多进程

改造完成后真开过多实例验证（3 个 API 实例 + nginx，并发 10 个真实对话时重启一个 worker，零误伤），确认改造成立。**但最终没采用多实例。**

理由：项目定位是「单用户、本机或可信内网部署」，多实例换来的两个好处——**不中断**和**能扩容**——都用不上。多实例还要额外维护分发层、选主锁、心跳判据，收益为零、成本为正。

最终形态是**单实例多进程**：1 个 API 进程 + 3 个 worker 进程，并发靠各队列的 `max_jobs` 调。多实例所需的代码能力（状态外置、取消信号、会话锁）保留着，需要时加上分发层即可。

### 明确不做

- **不引入鉴权与多租户**：项目定位为单用户。
- **不更换向量库为 pgvector**：换库需重跑全量 embedding 并重新标定召回。
- **不用 MySQL FULLTEXT 替换 BM25**：中文分词质量不可退。
- **不维护多数据库方言**：只支持 MySQL 一种。

## 结果

- 索引延迟由平均 2.5 秒（轮询周期一半）降至接近 0。
- 进程重启不再丢任务：任务状态落在数据库表里，worker 崩溃后有兜底扫描回收。
- 长任务不再堵短任务：三个队列分开排队。
- 对话可以断线续传：事件流外置到 Redis Stream，刷新页面或网络抖动后能从上次位置接着听。**这一条单实例下同样受益**，与多不多实例无关。
- 部署复杂度上升：容器由 1 个增加到 7 个，需要 healthcheck 编排。
- 运维成本上升：MySQL 与 Redis 需要备份与监控，原先只需备份单个 `.db` 文件。

### 过程中修掉的真实缺陷

这几处是多实例验证**照出来的**——单实例下看不见，但都是真缺陷：

1. **API 启动会误伤 worker 正在跑的索引任务**。启动时无差别地把所有 `processing` 任务改回 `pending`，这个前提只在「索引执行和 API 同进程」时成立。
2. **应用绑回环地址导致容器之间连不上**。单实例下察觉不到，因为从宿主机访问依然通。
3. **迁移链的 downgrade 在 MySQL 上跑不通**。原先的「先删索引再删表」序列是 Alembic 在 SQLite 环境下 autogenerate 生成的，MySQL 不允许删除被外键需要的索引（错误 1553）。
